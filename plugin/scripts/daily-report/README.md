# daily-report

에이전트가 남긴 날짜별 결과 파일(`docs/result-format.md`, format_version 1)을 합쳐 매일 오전 10시에 시작하는 루틴이 대표에게 보낼 보고서 HTML 한 장과 실행 기록을 만듭니다. Python 3.13과 표준 라이브러리만 쓰고, 네트워크에 접근하지 않습니다.

## 실행 방법

```
python -m daily_report build --date 2026-11-05 --results <결과 폴더> --out <출력 폴더> [--settings <설정 폴더>] [--runs <실행 기록 폴더>]
python -m daily_report record-publish --runs <실행 기록 폴더> --date 2026-11-05 --at 2026-11-05T10:58:00+09:00 --ok true
python -m daily_report arrival-rate --runs <실행 기록 폴더> --from 2026-11-02 --to 2026-11-06 [--deadline 11:00]
```

- `build`는 `<출력 폴더>/report-<날짜>.html`을 씁니다. `--runs`를 주면 `runs.jsonl`에 한 줄을 추가합니다.
- 시험: `cd daily-report; python -m unittest discover -s tests -v`
- 샘플: `sample/sample-report.html`은 `tests/fixtures`의 고정 자료로 만든 것입니다.

## 역할의 경계

- 이 코드는 **호출된 시점에 있는 결과 파일만으로** 보고서를 만듭니다. 10:50 시간 상자(늦는 소스는 기다리지 않고 나머지로 만든다)는 **호출하는 Claude 예약 작업의 일**입니다. 10:50에 도착해 있지 않은 결과 파일은 '결과 없음'으로 표시됩니다.
- 게시(artifact)는 이 코드의 일이 아닙니다. 예약 작업이 만들어진 HTML을 게시하고, 결과를 `record-publish`로 기록합니다.
- 기대하는 에이전트 목록은 `daily_report/inputs.py`의 `EXPECTED_AGENTS`입니다. 시장 정보 에이전트는 여기에 `"market"`을 더하면 읽습니다. 표시 절은 market-agent spec이 정한 뒤 `render.py`의 `SECTIONS`에 더합니다.

## 동작 요약

- 파일이 없으면 '결과 없음', 읽을 수 없거나 형식 버전이 `"1"`이 아니거나 필수 필드가 없거나 `run_date`가 다르면 '형식 오류'입니다. 어제 파일로 대체하지 않습니다(전날 파일은 건수 비교에만 씁니다).
- 계약 문서의 목록에 있는 필드만 읽습니다. 오류 `message`와 `attachments`도 읽지 않습니다. 링크의 인증키 매개변수(`serviceKey=` 등)는 지우고, `http`와 `https`가 아닌 주소는 링크로 만들지 않습니다.
- 보기 위젯(정렬, 마감 임박만 보기, 모두 접기와 펼치기)은 순수 화면 조작입니다. 저장, 내려받기, 외부 스크립트와 글꼴, `window.claude`를 쓰지 않습니다. 스크립트가 꺼져 있으면 도구 모음이 숨겨진 채로 `<details>`만으로 읽힙니다.
- 글꼴은 시스템 글꼴 목록(Pretendard가 설치돼 있으면 사용, 없으면 맑은 고딕 등)이며 내려받지 않습니다.
- 실행 기록 한 줄: 날짜, 시작과 종료 시각, 소스별 성공 여부와 사유 종류, `report_ok`, `published_ok`(게시 전 null), 게시 뒤 `published_at`과 `publish_late`.
- 도착률: 기간의 모든 날짜가 분모이고, 기록이 없는 날은 미실행입니다. 마감 시각(기본 11:00 정각 포함, `runs.py`의 `DEADLINE`)까지 게시에 성공한 날만 분자입니다. 같은 날 여러 줄이면 하나라도 도착이면 도착입니다.

## 가정 목록 (대표가 정한 것이 아니므로 확인이 필요합니다)

1. 오늘 볼 3건: 새 입찰공고와 지원사업 중 마감이 가까운 순(마감 없음은 뒤), 같으면 일치 키워드가 많은 순. 민간 외주 글은 고르지 않습니다. 이미 마감이 지난 항목은 고르지 않습니다.
2. 마감 임박: 마감까지 0~7일인 입찰공고와 지원사업. D-day는 `deadline`과 `--date`로 계산하며 결과 파일의 `dday`는 읽지 않습니다.
3. 최근 설정 변경: 기준일 기준 0~7일 이내(7일 전 포함, 미래 일자 제외).
4. 전날 대비 건수: 오늘과 전날 모두 수집에 성공한 소스의 `included`와 `excluded`만 합산합니다. 실패 소스를 넣으면 0건이 변화로 보이기 때문입니다.
5. 수집에 실패한 날은 "오늘은 새 공고가 없습니다"를 쓰지 않습니다. 새 공고가 없는 것과 확인하지 못한 것을 구분하기 위해서입니다. 성공한 소스가 있으면 "수집에 성공한 소스에는 오늘 새 항목이 없습니다", 하나도 없으면 "오늘 결과 파일을 확인하지 못했습니다"를 씁니다.
6. 상단에 올린 항목(오늘 볼 3건, 마감 임박)은 소스별 절에서 중복해 보이지 않습니다. 나머지는 절마다 `<details>` 하나에 접어 둡니다.
7. 에이전트 전체가 실패하면 마지막 정상 수집 시각을 알 수 없어 '확인 불가'로 표시합니다.
8. 10:50 시간 상자와 11:00 도착 기준은 2026-11-09에 정했습니다(`docs/decisions.md` D5). 7일 기간은 spec의 '제안'이며 확정되지 않았습니다.
