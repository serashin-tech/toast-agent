# gov-agent (정부사업 에이전트)

공공데이터포털 API 3종(입찰공고, 한콘진 지원사업, 중소기업 지원사업)과 CGLink 외주발주 게시판 RSS를 하루 한 번 수집해 날짜별 결과 파일 `gov_<날짜>.json`을 만듭니다. 형식은 `../docs/result-format.md`가 정본입니다. Python 3.13 표준 라이브러리만 쓰며 설치할 패키지가 없습니다.

## 실행

```
python -m gov_agent run --date 2026-11-11 --out <결과 폴더> [--settings <설정 폴더>] [--state <상태 폴더>] [--env-file <.env 경로>]
python -m gov_agent eligibility --input 요건.json [--settings <설정 폴더>] [--out 결과.json] [--merge-into <하루치 결과 파일>]
python -m gov_agent brief --input 신호.json [--eligibility 검토결과.json] [--settings <설정 폴더>] [--out brief.json]
```

- `brief`는 2차 검토(시연 판정)입니다. 입력 형식과 판정 규칙은 `docs/demo-brief-input.md`입니다. 공고 1건의 2차 검토 절차는 `review-requests` 스킬, 1차 시연 데모 절차는 `make-demo` 스킬입니다.

- 기본 설정 폴더는 작업 폴더의 `settings`, 기본 상태 폴더는 작업 폴더의 `state`, 기본 `.env`는 작업 폴더의 `.env`입니다(현재 폴더 기준).
- 인증키는 환경변수 `DATA_GO_KR_SERVICE_KEY` 또는 `.env`(`KEY=값` 형식)에서만 읽습니다. 환경변수가 `.env`보다 우선합니다. 작업 루트의 `.env.example`을 복사해 채웁니다. 키는 결과 파일, 상태 파일, 오류 메시지에 남지 않습니다.
- CGLink RSS(`https://cglink.com/jobsOffer/rss`)는 인증키 없이 읽으므로, 키가 없는 날에도 이 소스는 수집됩니다.
- 한콘진 요청 주소는 `KOCCA_API_URL`에 넣습니다. 비어 있으면 그 소스만 `format` 오류로 실패하고 나머지는 수집합니다. 입찰공고와 중소기업 지원사업의 요청 주소는 기본값이 있으며, 실제 응답을 확인한 뒤 바꿔야 하면 `BID_API_URL`, `BIZINFO_API_URL`로 덮어씁니다.
- `eligibility --merge-into`는 검토 결과를 하루치 결과 파일의 `eligibility` 배열에 합칩니다. 같은 공고번호는 바꾸고 새 공고는 더합니다.
- 소스 하나가 실패해도 결과 파일은 항상 써집니다. 실패 사유는 `sources[].error.kind`(`auth`, `pending_approval`, `rate_limit`, `network`, `format`)에 남습니다.

## 시험

```
cd gov-agent
python -m unittest discover -s tests -v
```

시험은 네트워크를 쓰지 않습니다. 가짜 응답(`tests/fixtures.py`)으로 수집 전체(경계 A)와 제안 가능성 검토(경계 B)를 검증합니다.

## 설정 파일 (`settings/*.md`)

값 영역은 `## 변경 이력` 절 앞의 표이고, 코드는 이 영역만 읽습니다. 변경 이력 절은 읽지 않습니다. 값을 고치면 같은 파일의 변경 이력에 한 줄 남깁니다. 값이 비어 있으면 그 조건은 적용하지 않습니다.

| 파일 | 열과 행 |
|---|---|
| `bid-filter.md` | 열 `항목 / 값 / 비고`. 행: 포함 키워드, 제외 키워드, 추정가격 최소, 추정가격 최대, 마감까지 최소 남은 일수, 제외할 기관 유형. 키워드는 쉼표 구분 |
| `grant-criteria.md` | 열 `항목 / 값`. 행: 관심 기관, 사업 분야, 지원사업 키워드, 제외 키워드 |
| `company-profile.md` | 열 `항목 / 값 / 확인 상태 / 출처`. 제안 가능성 검토만 읽음. 형식은 `docs/eligibility-input.md` |
| `demo-criteria.md` | 열 `항목 / 값 / 비고`. 행: 시연 신호 단어(쉼표 구분). 2차 검토만 읽음. 읽지 못하거나 비면 기본 단어를 쓰고 `settings_note`에 남김 |

`bid-filter.md`와 `grant-criteria.md`에는 2026-11-09에 대표 확인 전 초안 값을 넣었습니다(입찰공고 키워드는 `company-profile.md`의 사업 분야와 실적에서 뽑음). 값을 모두 비우면 모든 공고와 지원사업이 통과합니다. 낙찰정보 수집과 경쟁사 대조는 2026-11-09에 기능에서 뺐습니다(구현 PRD D15).

설정 파일에 오류(표 없음, 필수 행 없음, 숫자 아님)가 있으면 상태 폴더의 `last_good_settings/`(직전 정상 설정)로 실행하고 `settings.fallback_used`와 `fallback_reason`에 남깁니다. 그것도 없으면 기본값(전부 통과)으로 실행합니다. 직전 정상 설정은 설정에 오류가 없는 실행마다 갱신합니다.

## 동작 요약

- **증분**: 소스별 마지막 정상 수집 시각을 `state/state.json`에 둡니다. 실패한 날과 한도 임박으로 중단한 날은 갱신하지 않습니다. 처음 실행은 하루 전부터 조회합니다. 이미 본 항목은 내용이 같으면 다시 담지 않고, 내용이 바뀌면 `is_new=false`로 담습니다.
- **호출 예산**: 소스별 하루 900회(기본)를 세어 넘기면 그 소스를 중단하고 `status=limit_near`(`error.kind=rate_limit`)로 남깁니다. 같은 날 여러 번 실행해도 합산합니다.
- **지원사업 병합**: 한콘진과 중소기업 지원사업이 같은 사업이면 한 건으로 합칩니다. 대표는 중소기업 쪽, 빈 필드는 한콘진으로 채우고 `origins`에 둘 다 넣습니다. 한 곳에만 있는 사업은 그 소스 id를 `source`로 씁니다.
- **민간 외주(CGLink)**: 대표가 요청한 '일반 업체 외주용역' 수집원입니다. RSS의 제목, 게시자 닉네임, 게시일, 원문 링크만 담고 본문은 읽지 않습니다(연락처가 섞일 수 있음). 한 달에 몇 건뿐이라 입찰공고 필터를 적용하지 않고 새 글을 모두 싣습니다. 처음 실행은 최근 14일치, 이후는 마지막 정상 수집일 이후 글만 담습니다. 나라장터에 올라오는 민간 제작사의 외주 발주(콘진원 지원사업 수행사 등)는 입찰공고 소스가 이미 수집합니다.
- **첨부 변환**: `gov_agent/converter.py`는 외부 명령 호출 자리와 '읽지 못함' 처리만 있습니다. 변환과 요건 추출은 Claude 세션이 합니다. hwp·hwpx는 kordoc 스킬, 그 밖의 파일은 markitdown으로 읽습니다(`docs/decisions.md` D27).

## 미확인 가정 목록

승인된 키로 실제 응답을 받기 전에는 아래가 모두 가정입니다. 각 항목은 `gov_agent/sources/<소스>.py` 맨 위 설명과 대응표(`FIELDS`)에서 한 곳에 모여 있어 바꾸기 쉽습니다.

1. **공공데이터포털 3종 모두 JSON 필드 이름이 가정입니다.** 시험의 고정 응답(`tests/fixtures.py`)도 실제 응답이 아니며 가정한 이름으로 만들었습니다. 실제 응답을 받으면 두 곳을 함께 교체해야 합니다.
2. 응답 구조를 `response.header.resultCode`, `response.body.items`, `response.body.totalCount`(data.go.kr 공통 모양)로 가정했습니다. 중소기업 지원사업과 한콘진은 다를 수 있습니다.
3. 입찰공고의 영문 오퍼레이션 이름(`getBidPblancListInfoServc`), `inqryDiv=1`의 뜻, 조회 기간 12자리 형식이 가정입니다.
4. 한콘진은 요청 주소와 파라미터를 모릅니다. 주소는 `KOCCA_API_URL`로만 받고, 증분 파라미터가 없다고 보고 전체를 받은 뒤 등록일로 로컬에서 증분을 판정합니다.
5. 중소기업 지원사업의 증분은 `updtPnttm`에 마지막 정상 수집 시각(12자리)을 넣는 방식으로 가정했습니다. 신청기간은 한 문자열(`시작 ~ 종료`)로 온다고 가정했습니다. 요청 주소의 오퍼레이션 경로는 기본 주소 그대로입니다.
6. 인증키 인코딩: 키를 한 번 디코딩한 뒤 요청 때 인코딩합니다(Encoding 키와 Decoding 키 어느 쪽을 넣어도 되게 한 가정).
7. data.go.kr 오류 분류(문자열과 코드 20, 22, 30~33)와 JSON 응답 코드 `03`(자료 없음)은 공통 오류 코드 문서를 바탕으로 한 가정입니다. 실제 응답으로 확인이 필요합니다.
8. **지원사업 병합 기준(정규화한 제목과 접수 마감일이 같음)은 사용자 확인 전의 가정입니다.**
9. 지원사업 필터는 관심 기관, 사업 분야, 키워드 중 **하나라도** 맞으면 통과하는 방식입니다. 이 결합 방식은 제가 정했습니다. 키워드는 제목과 사업개요에서 찾습니다.
10. (삭제, 2026-11-09) 경쟁사 대조는 기능에서 뺐습니다.
11. 입찰공고 필터의 제외 기관 유형은 응답의 기관 구분 필드(`insttDivNm`, 가정)와 대조합니다. 이 필드가 없으면 적용되지 않습니다. 추정가격이나 마감일이 없는 공고는 해당 조건에서 제외하지 않습니다. 업무구분 용역은 용역 목록 오퍼레이션을 호출하는 것으로 갈음하며 응답에서 다시 검사하지 않습니다.
12. 소재지 대조는 광역 지자체의 공식 이름과 줄임 이름을 같은 곳으로 보고(전북특별자치도, 전라북도, 전북), 서로 다른 광역 지자체로 확인될 때만 `unmet`입니다. 시·군만 적힌 요건처럼 판단할 수 없으면 `needs_check`입니다(2026-11-05 수정, 틀린 미충족이 비권고로 이어지는 것을 막기 위함).
13. 직접생산확인 같은 확인류 값은 `보유`, `미보유` 같은 표기를 가정합니다(`docs/eligibility-input.md`). 현재 프로필은 모두 대표 확인 필요라 11/5 기준으로는 전부 `needs_check`입니다.
14. 호출 예산 900회는 서비스별인지 계정 합산인지 모르는 일일 한도 1,000건에 여유를 둔 값이며, 소스별로 셉니다.
15. (정함, 2026-11-09 D27) 첨부는 hwp·hwpx면 kordoc 스킬, 그 밖이면 markitdown으로 읽습니다. 스캔 이미지로 된 PDF처럼 텍스트가 나오지 않는 파일은 '읽지 못함'으로 남습니다.
16. CGLink RSS는 최근 글만 담습니다(2026-11-09 기준 약 30건, 석 달 넘는 분량). 며칠 동안 수집에 실패해도 RSS 범위 안이면 다음 성공 때 따라잡지만, 그 범위를 넘으면 놓칩니다. 응답 모양은 2026-11-09의 실제 RSS로 확인했습니다.
