# 수집 이력 시트 Apps Script

`Code.gs`를 토스트 명의 Google 계정의 시트에 붙여 웹 앱으로 배포합니다(D19). 이 코드는 Google 쪽에서 돌기 때문에 저장소의 자동 시험으로 확인하지 못합니다. 아래 '확인 절차'를 실제 시트에서 한 번 실행하고 결과를 남깁니다.

## 설치

1. 토스트 명의 계정으로 빈 Google 시트를 만듭니다.
2. 확장 프로그램 > Apps Script에서 `Code.gs` 내용을 붙여 넣습니다.
3. 프로젝트 설정 > 스크립트 속성에 `TOKEN`(임의의 긴 문자열)과 `CEO_EMAIL`(대표 메일 주소)을 넣습니다. 이 두 값은 문서나 저장소에 적지 않습니다.
4. 편집기에서 `installTrigger`를 한 번 실행해 새벽 6시 정리 트리거를 만듭니다. 처음 실행할 때 권한 허용 창이 뜹니다.
5. 배포 > 새 배포 > 웹 앱: 실행 사용자는 '나', 액세스 권한은 '모든 사용자'로 둡니다. 대표 PC의 파이썬이 Google 로그인 없이 부르기 때문이며, 대신 모든 요청은 `TOKEN`이 맞아야 처리됩니다.
6. 배포 주소와 토큰을 대표 PC 작업 폴더의 `.env`에 `SHEET_APP_URL`, `SHEET_APP_TOKEN`으로 넣습니다.

## 확인 절차 (설치 후 한 번)

| 확인할 것 | 방법 | 기대 결과 |
|---|---|---|
| 토큰 검사 | 토큰 없이 `report.py sheet-pull` 실행(`.env`에서 토큰을 잠시 지움) | 실패 한 줄, 시트 변화 없음 |
| 행 추가 | 가짜 결과 파일로 `report.py sheet-push` | '수집 이력' 탭에 행이 생기고 상태는 '신규' |
| 상태·메모 보존 | 시트에서 상태를 '보류'로, 메모를 적은 뒤 같은 행을 다시 push | 상태와 메모가 그대로 |
| 메일 | `report.py mail`로 본문을 만든 뒤 `report.py send-mail` | 대표 주소로 메일 도착 |
| 정리 | 마감일을 어제로 고친 행 둘(하나는 메모 있음)을 두고 `cleanup` 실행 | 메모 없는 행은 지워지고, 메모 있는 행은 '지난 공고' 탭으로 옮겨짐 |

## 알려진 한계

- 웹 앱 주소와 토큰을 아는 사람은 시트를 읽고 쓸 수 있습니다. 토큰이 새면 스크립트 속성의 `TOKEN`을 바꾸고 `.env`도 고칩니다.
- 대표 메모는 `rows` 응답에 내용을 넣지 않고 있는지만(`has_memo`) 넣습니다. 사업 현황판(공유될 수 있는 페이지)의 관심사업 탭에는 '메모 있음'만 나오고 내용은 나오지 않습니다.
