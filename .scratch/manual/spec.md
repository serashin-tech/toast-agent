## Problem Statement

토스트 대표와 11월 25일 뒤에 시스템을 이어받을 관리자는 토스트 에이전트가 무엇으로 이루어졌고, 매일 무엇을 하며, 어떻게 설치하고 쓰는지 한곳에서 볼 수 없습니다. 지금 설명은 저장소의 `README.md`, `ARCHITECTURE.md`, 스킬 본문, `apps-script/README.md`에 흩어져 있고, 개발자를 위한 문장이라 대표가 읽기 어렵습니다. 설정값(입찰 필터, 지원사업 조건, 회사 프로필, 시연 기준)은 대표 PC의 마크다운 파일 안에 있어서, 대표는 현재 값이 무엇인지 보려면 파일을 열어야 하고, 바꾸려면 Claude에게 무엇을 어떻게 말해야 하는지 알아야 합니다.

설명서 artifact는 2026-11-11에 만들어 게시했지만, 원본이 세션 임시 폴더에만 있었고 명세가 없어 다음 사람이 이어서 고칠 기준이 없습니다.

## Solution

글을 줄이고 도식 위주로 만든 설명서 한 장을 claude.ai artifact로 게시하고, 원본은 저장소 `docs/manual/`에 둡니다. 탭은 다섯 개이며 순서는 아키텍처, 루틴 흐름도, 관리자 설정, 설치 방법, 사용 방법입니다. 관리자 설정 탭은 설정 파일 4종의 현재 값을 세부 탭으로 보여 주고, 대표가 화면에서 값을 고치거나 추가하면 Cowork에 붙여 넣을 변경 요청문을 만들어 줍니다. 실제 반영은 change-setting 스킬이 하므로, 확인 절차와 변경 이력 규칙(D11, 불변 규칙 3)은 그대로 지켜집니다. 아직 준비되지 않은 내용은 '준비 중' 자리로 남겨 두고 나중에 채웁니다.

## User Stories

1. 대표로서, 토스트 에이전트가 어디서 공고를 모아 어디로 보내는지 그림 한 장으로 보고 싶습니다. 그래야 설명을 듣지 않고도 전체를 이해할 수 있습니다.
2. 대표로서, 토스트 에이전트 안에 정부사업 에이전트와 시장 정보 에이전트가 있고, 시장 정보 에이전트는 준비 중이라는 것을 구분해서 보고 싶습니다. 그래야 지금 무엇을 기대할 수 있는지 압니다.
3. 대표로서, 정부사업 에이전트가 하는 일을 '공고 모으기 · 1차 필터링 · 2차 검토(참가자격·시연)'처럼 시트 상태와 같은 말로 보고 싶습니다. 그래야 시트의 상태 이름과 설명서를 맞춰 볼 수 있습니다.
4. 대표로서, 설정·키·수집 결과가 GitHub에는 없고 내 PC에만 있다는 것을 알고 싶습니다. 그래야 저장소를 공유해도 안심할 수 있습니다.
5. 대표로서, 매일 10시 루틴이 어떤 단계로 돌고 언제 메일이 도착하는지(10:00 시작, 10:50 마감, 11:00 도착) 보고 싶습니다. 그래야 메일이 늦을 때 어디서 막혔는지 짐작할 수 있습니다.
6. 대표로서, 하루 동안 자동으로 도는 일(06:00 시트 정리, 30분마다 2차 검토 확인, 10시 루틴)을 시간 막대로 보고 싶습니다.
7. 대표로서, 공고 상태가 어떤 순서로 바뀌고 그중 무엇을 내가 바꾸고 무엇을 에이전트가 바꾸는지 색으로 구분해 보고 싶습니다.
8. 대표로서, 설정 파일 4종의 현재 값을 파일을 열지 않고 보고 싶습니다.
9. 대표로서, 설정을 회사 프로필, 입찰공고 필터, 지원사업 검색 조건, 시연 판정 기준의 세부 탭으로 나눠 보고 싶습니다. 그래야 한 번에 한 가지 설정만 보며 고칠 수 있습니다.
10. 대표로서, 입찰 필터와 지원사업 조건이 아직 '대표 확인 전 초안'이라는 표시를 보고 싶습니다. 그래야 확인해야 할 값을 먼저 봅니다.
11. 대표로서, 키워드를 칩으로 빼거나 더하고, 숫자 항목은 숫자만 입력하고 싶습니다.
12. 대표로서, 회사 프로필의 값과 확인 상태(확인됨, 일부 확인, 추정)를 바꾸고, '수행 실적 7' 같은 새 항목을 추가하고 싶습니다.
13. 대표로서, 바꾼 값 옆에서 원래 값을 함께 보고 싶습니다. 그래야 무엇을 바꿨는지 헷갈리지 않습니다.
14. 대표로서, 세부 탭마다 바꾼 건수를 보고 싶습니다. 그래야 다른 탭으로 옮겨도 고친 것을 잊지 않습니다.
15. 대표로서, 고친 내용을 모은 변경 요청문을 복사해 Cowork에 붙여 넣기만 하면 되기를 원합니다. 그래야 Claude에게 어떻게 말할지 고민하지 않습니다.
16. 대표로서, 요청문에 요청자와 사유를 넣고 싶습니다. 그래야 변경 이력의 사유·변경자 칸이 채워집니다.
17. 대표로서, 이 화면에서 고친 것만으로는 실제 설정이 바뀌지 않는다는 안내를 보고 싶습니다. 그래야 반영됐다고 착각하지 않습니다.
18. 대표로서, 실수로 고친 것을 한 번에 되돌리고 싶습니다. 다만 한 번 눌러서 바로 지워지지 않기를 원합니다.
19. 대표로서, 실행 시각, 단계 마감, 시트 정리 시각, 인증키처럼 이 화면에서 바꾸지 않는 값은 어디서 바꾸는지 알고 싶습니다.
20. 대표로서, 인증키와 시트 주소는 설명서에 나오지 않기를 원합니다.
21. 대표로서, GitHub 초대 수락부터 저장소 받기, Cowork 플러그인 설치, 작업 폴더, Apps Script, 예약 작업, 확인까지 순서대로 따라 하고 싶습니다.
22. 대표로서, 명령어와 저장소 이름, 예약 작업 지시문을 복사 단추로 복사하고 싶습니다.
23. 대표로서, 마켓플레이스 추가가 안 될 때의 대안(plugin 폴더 업로드)을 같은 자리에서 보고 싶습니다.
24. 대표로서, 매일 내가 하는 일(메일 확인, 시트 상태 바꾸기, 현황판 보기)을 세 가지로 보고 싶습니다.
25. 대표로서, Claude에게 말로 시킬 수 있는 문장 예시와 그 결과를 보고 싶습니다.
26. 대표로서, 휴대폰에서도 가로 스크롤 없이 읽고 싶습니다.
27. 관리자로서, 설명서 원본이 저장소에 있어서 다음 사람이 같은 파일을 고쳐 같은 주소에 다시 게시할 수 있기를 원합니다.
28. 관리자로서, 설정 항목이 코드에서 추가되거나 이름이 바뀌면 설명서가 낡았다는 것을 시험으로 알고 싶습니다.
29. 관리자로서, 준비 중인 내용(설치 화면 캡처, 업데이트 방법, 메일·현황판 예시 화면, 시장 정보 에이전트 사용 방법)이 어디에 들어갈지 자리로 보고 싶습니다.
30. 코드프레소 담당자로서, 설명서가 코드프레소 브랜드 값(메인 파랑, 노랑 강조 1~2곳, 한글 어절 줄바꿈)을 따르기를 원합니다.

## Implementation Decisions

- **원본과 게시**: 설명서는 HTML 한 장이고, 로고 두 개(밝은 화면용, 어두운 화면용)를 data URI로 넣은 완성본이 저장소 `docs/manual/`의 정본입니다. 빌드 단계는 두지 않습니다. 게시할 때는 Artifact 도구가 작업 폴더나 스크래치패드의 파일만 받으므로 정본을 스크래치패드로 복사해 같은 주소(https://claude.ai/artifact/2QvsLa7X36TySdGDQRKRGw)에 다시 게시합니다. 게시한 뒤 정본과 게시본이 같은지 확인합니다.
- **탭**: 아키텍처, 루틴 흐름도, 관리자 설정, 설치 방법, 사용 방법 순서입니다. 탭은 주소의 `#architecture`, `#routine`, `#admin`, `#install`, `#usage`로 바로 열립니다. 이 이름은 이미 전달한 링크가 있으므로 바꾸지 않습니다.
- **용어**: '1차 필터링', '2차 검토'를 씁니다. '2차 조건검토'로 바꾸지 않습니다. 2차 검토는 참가자격 대조와 시연 판정을 함께 하고, 시트 상태 값('2차 검토 요청', '2차 검토 중', '2차 완료')과 이름이 같아야 하기 때문입니다(2026-11-11 사용자 결정).
- **관리자 설정의 쓰기 경로**: 설명서는 설정 파일에 쓰지 않습니다. 화면에서 고친 내용은 변경 요청문으로만 나가고, 대표가 그 문장을 Cowork에 붙여 넣으면 change-setting 스킬이 전후를 보여 주고 확인받은 뒤 파일 전체를 다시 쓰며 변경 이력을 남깁니다(D11, 불변 규칙 3). artifact의 런타임 기능(공유 저장소 등)은 선언하지 않습니다(불변 규칙 4).
- **현재 값**: 설명서 안의 설정값은 게시 시점의 스냅샷이며, 기준일을 화면에 적습니다(지금은 2026-11-11, `07_Implementation/gov-agent/settings/`). 설정이 바뀌면 설명서도 다시 게시해야 갱신됩니다. 회사 프로필은 항목·값·확인 상태만 보이고, 출처 칸은 넣지 않습니다.
- **세부 탭**: 회사 프로필, 입찰공고 필터, 지원사업 검색 조건, 시연 판정 기준 순서입니다. 처음에는 회사 프로필이 열리고, 마지막으로 본 세부 탭과 작성 중인 변경 내용은 그 사람의 브라우저에만 저장됩니다. 저장 형식의 기준값을 바꾸면(예: 항목 순서 변경) 이전에 작성하던 내용은 버립니다.
- **변경 요청문 형식**: 첫 줄에 "toast-agent 설정을 아래와 같이 바꿔 줘. 바꾸기 전후를 보여 주고 내가 확인한 뒤 반영해 줘."를 두고, 설정 파일마다 `[설정 이름] settings/<파일>` 아래에 목록 항목은 `추가 '값' / 삭제 '값'`, 숫자 항목은 `이전 → 이후`, 회사 프로필은 `'이전 값' (상태) → '새 값' (상태)`와 `새 항목 추가: 이름 = '값' (상태)`로 적습니다. 끝에 사유와 요청자를 붙입니다.
- **여기서 바꾸지 않는 값**: 루틴 시작과 2차 검토 간격은 Cowork 예약 작업, 단계 마감과 도착 기준은 프로그램, 시트 정리는 Apps Script 트리거, 인증키와 시트 주소는 작업 폴더의 `.env`에서 바꾼다고 안내만 합니다. 키 값은 화면에 없습니다(불변 규칙 1·2).
- **설치 경로**: GitHub 비공개 저장소 `serashin-tech/toast-agent` 초대 수락 → clone 또는 ZIP → Cowork 마켓플레이스 추가(안 되면 `plugin` 폴더 업로드, H14) → 작업 폴더에 `settings/`(템플릿 4개 복사)와 `.env` → Apps Script → 예약 작업 2개(`/toast-agent:daily-routine` 평일 10:00, `/toast-agent:review-requests` 09~18시 30분마다) → "오늘 루틴 다시 돌려 줘"로 확인.
- **브랜드와 조판**: 코드프레소 브랜드 가이드의 값(메인 파랑 `#1961E9`, 노랑은 11:00 도착 표시와 '대표가 바꿈' 상태에만), 한글 `keep-all` 줄바꿈, 밝은·어두운 화면 두 테마를 씁니다. 로고는 바닥글에만 둡니다. Pretendard는 artifact 보안 정책상 불러올 수 없어 설치되지 않은 PC에서는 맑은 고딕으로 보입니다.
- **문체**: 5쪽 이하 자료이므로 개조식이고, 조사는 생략하지 않으며 엠대시를 쓰지 않습니다.

## Testing Decisions

- 좋은 시험은 게시되는 HTML 파일 한 장을 밖에서 보듯 읽고, 대표에게 보이는 결과만 확인합니다. 화면 동작(탭 전환, 칩 추가)은 자동 시험으로 보지 않고 게시 전 브라우저 확인으로 대신합니다.
- **시험하는 자리는 하나입니다: 저장소의 설명서 정본 파일**(2026-11-11 사용자 확인). 플러그인 시험 묶음에 시험 하나를 더해 `run_tests.py`가 함께 돌게 합니다.
  - 설명서에 메일 주소, `.env` 항목에 값이 붙은 줄, 토큰처럼 보이는 긴 문자열이 없는지(불변 규칙 2)
  - 설명서 관리자 설정의 항목 이름이 `settings-template/`의 네 파일 `## 값` 표의 항목 이름과 같은지. 코드에서 설정 항목을 더하거나 이름을 바꾸면 이 시험이 실패해 설명서도 고치게 됩니다. 회사 프로필은 대표 PC에서 항목이 늘 수 있으므로, 템플릿에 있는 항목이 설명서에 모두 있는지만 봅니다.
  - 탭 다섯 개의 `#` 이름이 그대로인지(이미 전달한 링크 보호)
- 선례: `plugin/tests/`의 플러그인 구조 시험처럼 파일을 읽어 구조를 확인하는 방식입니다.

## Out of Scope

- 설명서가 대표 PC의 설정 파일을 직접 읽거나 쓰는 것. 설정을 바꾸는 길은 change-setting 하나입니다.
- 설정이 바뀔 때 설명서를 자동으로 다시 게시하는 것. 지금은 사람이 다시 게시합니다.
- 설명서를 대표에게 공유하는 일(artifact의 Share 메뉴에서 사용자가 직접 함).
- '준비 중' 자리의 내용(설치 화면 캡처, 업데이트 방법, 메일·현황판 예시 화면, 시장 정보 에이전트 사용 방법). 내용이 생기면 이 명세에 따라 같은 파일에 채웁니다.
- 시장 정보 에이전트 연결(PRD Q9).

## Further Notes
